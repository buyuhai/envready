# EnvReady 设计文档 12 —— 日志、诊断与支持

> 面向的场景：学生在宿舍里装失败了，身边没人能帮。他唯一能做的事是
> "把这个信息发给助教/开发者"。因此日志的设计目标有两个：
> **让我们能远程定位问题**，以及**让学生自己看懂"程序到底做了什么"**。

---

## 12.1 两类记录，用途完全不同

| 类型 | 面向谁 | 内容 | 位置 | 界面入口 |
|---|---|---|---|---|
| **操作记录** | 学生与助教 | 人话叙述："14:22 开始下载 C/C++ 编译器（约 107 MB）"；"14:23 下载完成并校验通过"；"14:24 已把 `.../bin` 加到 PATH（原值已备份）" | `<APP_ROOT>/logs/history.log` | 「我做过什么」页面（可视、可复制） |
| **诊断日志** | 开发者与助教排查 | 结构化字段：时间、级别、模块、组件、动作、耗时、结果、错误分类、堆栈（仅内部） | `<APP_ROOT>/logs/app-YYYYMMDD.log` | 隐藏，通过"查看详情/复制诊断信息"进入 |

**关键区别**：操作记录是**产品功能**（对应"所有事项要简单明白地告诉用户我们干了什么"），
不是调试副产品。它必须一直存在、必须是人话、必须可导出。

---

## 12.2 诊断日志规范

| 项 | 规范 |
|---|---|
| 格式 | 结构化 JSON Lines（每行一个 JSON 对象）——便于自动分析，也便于导出后处理 |
| 字段 | `time`（RFC3339，含时区）、`level`、`module`、`action`、`component`、`version`、`duration_ms`、`result`、`error_class`、`message`、`detail` |
| 级别 | `debug`（默认关闭，用户可在设置中开启）、`info`、`warn`、`error` |
| 轮转 | 按天切分；单文件超过 10 MB 切分；保留最近 14 天；超期自动删除 |
| 上限 | 任何单条消息截断到 4 KB（防止恶意/异常输出刷爆） |
| 编码 | UTF-8（带 BOM 以便 Windows 记事本正确显示中文） |

**`error_class` 必须取自 `01` 的错误分类枚举**（网络/上游变更/磁盘/权限/用户取消/程序缺陷）。
这条字段使我们能直接回答"用户失败的主要原因是什么"，
进而决定优化方向（例如若 60% 是网络，就该加强镜像与代理支持）。

---

## 12.3 必须记录的关键事件（清单）

下列事件**必须**留下记录；漏记视为缺陷。

| 分类 | 事件 |
|---|---|
| 启动 | 启动器启动、指针状态、最终选择的版本、修复模式是否触发 |
| 更新 | 检查清单、发现新版本、下载、校验、解压、切换指针、健康检查结果、回退 |
| 清单 | 拉取成功/失败、是否使用缓存或出厂快照、清单年龄、签名校验结果 |
| 下载 | 选中的镜像、URL（脱敏）、开始/结束、字节数、耗时、平均速度、重试次数与原因、校验和比对结果 |
| 安装 | 组件与版本、install_kind、解压工具选择（内置/tar.exe/7-Zip/7zr）、`expect_files` 校验结果 |
| 自检 | 执行的命令、退出码、输出版本号、判定结果（成功/警告/失败） |
| 环境变量 | 操作类型（activation/switch/uninstall）、目标项、旧值是否已备份、写入结果、广播结果、回读校验结果 |
| 恢复 | 检测到意图记录、用户选择完成或还原、结果 |
| 用户操作 | 授权询问的选择（同意/拒绝）、取消 |
| 崩溃 | panic（含堆栈，仅内部日志）、异常退出标记 |

**环境变量与安装相关的记录还有一层"审计"意义**：
当学生说"我的电脑坏了"时，我们能精确回答"我们在什么时间把这个值从 A 改成了 B"。

---

## 12.4 脱敏规则

日志会在用户主动提交时离开他的电脑，因此必须在**写入时**就脱敏（而不是导出时才处理）：

| 内容 | 处理 |
|---|---|
| 用户名 | 家庭路径中的用户名替换为 `<user>`（如 `C:\Users\alice\...` → `C:\Users\<user>\...`） |
| 主机名 / 域名 | 替换为 `<host>` |
| 代理地址中的凭证 | 只保留 `host:port`，用户名密码替换为 `<redacted>` |
| IP 地址 | 不记录 |
| 环境变量的**具体值** | 只记录"哪个变量、长度、路径的末两级"，不记录完整值（PATH 可能含用户私密目录名） |
| 完整 URL 的查询串 | 删除（签名参数含凭证；实测下载地址会带 SAS token / `sig` / `jwt`，这些必须不落盘） |

**"查询串必须删除"这条有实测依据**：Adoptium 的 JDK 地址会 302 到带
`se=…&sig=…&jwt=…` 的签名地址，这些参数就是临时凭证。

## 12.5 诊断包

用户点"复制诊断信息"时生成的文本（同时也提供"保存为文件"）：

```
目标：让学生只需点一下，然后粘贴到聊天窗口里
```

| 分段 | 内容 |
|---|---|
| 环境概要 | EnvReady 版本、启动器版本、操作系统与版本、架构、是否 64 位 |
| 存储概要 | APP_ROOT 与 ENV_ROOT 的**盘符与剩余空间**（不写完整路径中的用户名） |
| 指针状态 | 当前状态、当前版本、上一个版本、尝试次数 |
| 组件状态 | 每个组件：状态、激活版本、是否已装多版本、最近一次自检结果 |
| 网络概要 | 是否有代理（脱敏）、最近 5 次网络请求的结果与 `error_class` |
| 最近事件 | 最近 100 条 `info` 及以上记录（脱敏后） |
| 最近错误 | 最近 20 条 `error`，含 `error_class` 与上下文 |
| 已用清单 | 清单来源（在线/缓存/出厂快照）+ 年龄 + 签名状态 |

**不做的事**：不自动上传。生成后展示给用户看，由他决定是否发送。

**界面上的"隐私说明"**必须同时出现："这份信息里包含你的操作系统版本和程序运行记录，
不包含你的姓名、学号或任何文件内容。"

## 12.6 「我做过什么」页面（产品化的操作记录）

这是"过程可解释"原则最直接的落地，也是相对参考实现（只有一个 40% 高的黑话日志窗）
最明显的体验差异：

```
我做过什么

今天 14:22  安装了 C/C++ 编译器 14.2.0
            保存位置：D:\DevEnv\mingw\mingw-14.2.0
            做了设置：让命令行能找到它（原来的设置已备份）
            验证结果：gcc 报出版本 14.2.0 ✔

今天 14:24  为 C:\Users\alice\cpp-practice 生成了编辑器配置
            新建了 4 个配置文件；已有的同名文件已备份

昨天 20:10  更新了程序（1.0.0 → 1.1.0）

              [导出这些记录]  [恢复设置...]
```

- 每一条都能展开看细节（对应日志里的 `detail`）。
- "恢复设置"直接进入环境变量备份与还原（见 `07` 的 7.4.3）。
- 这个页面给学生的是**安全感**：他随时能查"这个软件到底动了什么"。

## 12.7 常见问题自愈（帮助页）

按"症状 → 可能原因 → 一键动作"组织，而不是按技术原因组织：

| 症状（学生的话） | 一键动作 |
|---|---|
| 装完了但命令行说找不到命令 | 「重新验证环境设置」+ 提示重开命令行窗口 |
| 下载一直失败 | 「换一个下载地址重试」+「检查代理设置」+「用离线安装包」 |
| 装到一半卡住了 | 「重试」+「清理未完成的文件」 |
| 编辑器里编译不了 | 「重新生成编辑器配置」 |
| 我把电脑弄坏了，想恢复 | 「恢复环境设置」（列出备份，一键还原） |
| 不确定装没装好 | 「全面检查」（对所有组件跑一遍自检并给出报告） |

**"全面检查"是学生最需要的功能之一**：他不知道"哪里不对"，
我们替他把所有环节查一遍并给出结论。

## 12.8 崩溃处理

| 情形 | 处理 |
|---|---|
| 后台任务 panic | `recover` 后记为 error，向界面报告该任务失败，**程序不退出** |
| 主程序崩溃 | 启动器感知到非零退出码并记录；下次启动时界面提示"上次程序异常退出"，提供「查看详情」与「回到上一个版本」 |
| 连续崩溃 3 次 | 停止自动重启，进入修复模式并提示重新安装（避免无限重启循环） |
| 崩溃日志 | panic 堆栈只写内部日志（脱敏），**绝不显示在界面上** |

参考实现的教训：它把 `traceback.format_exc()` 直接拼进用户可见的日志窗，
对零基础用户等于一屏天书，且破坏了"这是我的问题还是程序的问题"的判断。
