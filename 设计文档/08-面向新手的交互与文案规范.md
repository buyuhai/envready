# EnvReady 设计文档 08 —— 面向新手的交互与文案规范

> 本文档对应项目要求："面向对象主要是学生，所以 UI 简洁，操作过程中所有事项要简单明白地
> 告诉用户我们干了什么。"
> 参考实现（murig）在功能上已经验证了"一站式装配"可行，但它的界面语言是给有基础的人看的：
> 按钮写"配置环境变量"、报错直接打印 Python 调用栈、日志区固定占屏幕 40% 高度。

---

## 8.1 三条交互前提（决定所有设计取舍）

1. **学生不知道"该装什么"。** 他打开程序时脑子里只有一个模糊目标："我要学 Python"。
   因此第一屏不能是 29 张卡片的平铺列表，而应该是"你想学什么？"。
2. **学生怕把电脑弄坏。** 任何要改动系统设置的动作，都要先说清楚"我要做什么、能不能撤销"。
   （参考项目 `Install-MinGW.ps1` 的做法值得继承：**7 类有影响的操作逐项单独询问**。）
3. **学生事后记不住。** 装完之后他需要知道"下一步怎么做"，而不是"安装已完成"。

---

## 8.2 主流程（5 步，每一步一句话可讲清）

```
第 1 步  选目标      "你想学什么？"  →  C / C++、Python、Java、网页前端、不知道
第 2 步  确认清单     "我们会为你装这些"（列表 + 每项体积 + 合计体积 + 装在哪里）
第 3 步  开始安装     逐项进行：下载 → 解压 → 验证，每一项都有实时说明
第 4 步  结果确认     成功：验证过的版本号；失败：哪里失败、你可以怎么办
第 5 步  教你下一步   "打开一个新的命令行窗口，输入 gcc --version，应该看到……"
                     + 提供"用 VS Code 写第一个程序"的配置（见 09）
```

**"不知道"必须是一个正式选项。** 学生说不出语言名，只说得出口"我要写 C 语言作业"。
选"不知道"后走推荐路径（C/C++ 或 Python），并说明"我们按最常见的课程需求为你选了这些"。

---

## 8.3 界面结构

```
┌──────────────────────────────────────────────┐
│ EnvReady                      [设置] [关于]  │  标题栏（不用自绘的复杂标题栏）
├──────────────────────────────────────────────┤
│                                              │
│   主区域：一次只显示"当前该做什么"           │
│   （引导式，分步；不做多标签、不做长列表）     │
│                                              │
├──────────────────────────────────────────────┤
│ 状态/进度区：一句人话 + 进度条 + 速度/剩余时间 │
├──────────────────────────────────────────────┤
│ [查看详情 ▾]                                 │  折叠区：默认收起
└──────────────────────────────────────────────┘
```

**关于"运行日志"的取舍**（与参考实现的直接对照）：

参考实现把日志窗固定占 40% 屏幕高度，于是学生看到的是"一屏黑话"。
本项目原则：

- 日志**默认收起**，只在用户点"查看详情"时展开。
- 面向用户的主区域永远显示**经过人话翻译的一句话**。
- 详细日志用于"复制给助教/开发者"，提供"复制诊断信息"按钮。

## 8.4 术语 → 人话映射表

**这张表是硬约束：界面上不允许直接出现左列的词，必须用右列的说法。**
（左列允许出现在"查看详情"里。）

| 技术词 | 界面上对用户说 |
|---|---|
| 环境变量 | 让电脑知道软件装在哪儿的设置 |
| PATH | 让命令行能找到这些程序的列表 |
| `JAVA_HOME` / `XXX_HOME` | Java 装在哪里 |
| 配置环境变量 | 进行一次设置，让新开的命令行窗口能直接用 |
| 解压 | 把下载下来的压缩包打开 |
| 归档 / archive | 安装包 |
| 校验和 / SHA-256 | 检查文件有没有下载完整 |
| 依赖 | 装这个之前需要先装的东西 |
| 编译工具链 | 把 C 语言代码变成能运行的程序的那套工具 |
| 运行时 / runtime | 运行程序需要的软件 |
| 命令行 / 终端 | 黑色的输入命令的窗口（首次出现时给一句解释） |
| 版本号 | 这个软件的第几个版本 |
| 环境就绪 | 可以开始写代码了 |
| 上游 / 官方源 | 软件的官方网站 |
| 清单 / manifest | 资源列表 |
| 缓存 | 之前下载好的东西 |
| 自更新 | 程序自己升级 |
| 回滚 | 恢复到之前的样子 |
| 权限不足 | 这个位置不让你写文件 |

**使用注意**：映射不是"永远不出现技术词"，而是"首次出现时先给人话，再在括号里给技术词"，
例如："让电脑知道 Java 装在哪里（这个设置通常叫 `JAVA_HOME`）"。
学生迟早要在教程里遇到这些词，我们不该让他完全没见过——但绝不能用它当第一表述。

## 8.5 每一步的说明模板

任何一个耗时超过 2 秒的动作，主区域都必须显示下面四要素里的前两项，推荐全给：

| 要素 | 例子 |
|---|---|
| **正在做什么** | 正在下载 C / C++ 编译器（约 107 MB） |
| **为什么要做** | 这是把 C 语言代码变成程序所必需的工具 |
| **预计多久** | 已下载 45 MB，速度 2.1 MB/s，大约还需 30 秒 |
| **影响什么** | 会保存到 D:\DevEnv，不会改动系统设置 |

### 操作前的授权说明（继承自前期成果）

对下列有影响的操作，**逐项单独询问**，并且默认按钮是"取消"（安全默认）：

| 操作 | 询问文案 |
|---|---|
| 创建目录 | 要在 D:\DevEnv 新建一个文件夹吗？（这个文件夹用来放你装的环境） |
| 清空已有目录 | 这个文件夹里已经有东西了，继续会删除其中的文件。要看看到里面有什么吗？ |
| 联网下载 | 接下来要从官方网站下载文件（约 107 MB）。开始吗？ |
| 修改设置（环境变量） | 接下来要做一次设置，让命令行能找到刚装的程序。这个改动可以一键撤销。继续吗？ |
| 下载额外的解压工具 | 这个安装包需要一个小工具来解压（约 600 KB，来自 7-zip.org）。要自动下载吗？ |
| 提权（UAC） | 这一步需要管理员权限。可以不提权吗？——我们尽量不要求提权，若确实需要会解释原因 |

## 8.6 进度呈现规范

| 规则 | 说明 |
|---|---|
| 阶段要可见 | "下载中"与"解压中"必须是**不同的文字与阶段**，进度条可以重置。参考实现让学生在"100% 但没反应"里等 |
| 总大小未知时 | 显示已下载量 + 不确定进度条，**绝不显示假百分比** |
| 速度与剩余时间 | 必须显示；这是学生判断"卡住了还是在动"的唯一依据 |
| 长时间无变化 | 超过 15 秒没有新数据 → 主区域补一句"正在等待服务器响应，网络较慢时属正常" |
| 可取消 | 任何阶段都能取消；取消后状态回到"未安装"，不留半成品 |
| 不弹模态框 | 进度期间不用模态对话框挡住界面 |

## 8.7 结果页

### 成功时

```
✅ Python 已经装好了

  正在使用：Python 3.12.10
  安装位置：D:\DevEnv\python\python-3.12.10
  已验证：运行 python --version 得到 "Python 3.12.10"

  现在可以试试：
  1. 打开一个新的命令行窗口（怎么打开？）
  2. 输入：python --version        [复制]
  3. 如果看到 Python 3.12.10，就说明成功了

  [打开安装文件夹]  [接下来做什么？]
```

关键点：

- **展示自检的真实输出**，而不是"安装成功"四个字。
- **给出可自行验证的命令**，并带复制按钮（学生不擅长手打长命令）。
- 告诉用户"在哪里打开命令行"（参考实现从未提这件事）。
- 明确说出**人工操作提示**（`post_notes`）——参考实现把它打印在日志里，等于没说。

### 失败时

```
⚠️ Python 没能装好

  卡在哪一步：下载
  发生了什么：从官方网站下载时连接超时
  可能的原因：网络不通，或者学校网络需要代理
  你可以怎么做：
    ① 检查网络后重试        [重试]
    ② 如果你在学校网络里，可能需要填代理  [打开设置]
    ③ 用离线安装包          [选择文件]

  [查看详情]  [复制诊断信息]
```

**三行结构（发生了什么 / 为什么 / 你可以怎么做）是强制的**，
不允许出现"下载失败：HTTPError 403"这种把技术细节直接抛给用户的呈现。

## 8.8 文案写作规范

| 要求 | 反例 → 正例 |
|---|---|
| 用"你"不用"用户" | "用户需要重启终端" → "你需要重新打开命令行窗口" |
| 主动语态、第一人称复数可接受 | "配置失败" → "我们没能完成这次设置" |
| 不出现异常类型、栈、英文错误码 | "`SSL: UNEXPECTED_EOF`" → "连接被中断了" |
| 不用感叹号堆叠、不卖萌 | "哎呀！出错啦！！！" → "这一步没成功。" |
| 每次失败必须给出至少一条出路 | "安装失败" → "安装失败。你可以重试，或换用离线安装包" |
| 动词具体 | "处理中…" → "正在解压（还剩约 10 秒）" |
| 数字带单位与量级 | "107 MB"（学生看得懂 MB，看不懂 112000000） |
| 不承诺做不到的事 | 不写"永久有效""100% 不会出错" |

**需要特别避免的一类文案**：把决定权含糊地推给用户。
例如"是否继续？"不如"继续会修改你的设置（可以撤销），要现在做吗？"

## 8.9 依赖与冲突提示

| 情形 | 呈现 |
|---|---|
| 装 A 之前需要 B | "这个还需要先装 Node.js（约 30 MB）。要一起装吗？" [一起装] [只装我选的] |
| 系统已自带 | "你的 Mac 已经自带 Git，不需要额外安装。"（给出验证命令） |
| 已有同类的别家版本 | "检测到你电脑里已经有 Java（版本 17，装在 C:\Program Files\Java）。要另外装一个吗？还是就用现在这个？" |
| 端口/服务冲突 | 首期不涉及（数据库类组件不在首期范围） |

**绝不静默覆盖用户已有的东西**：检测到已有安装时，默认动作是"用现有的"，并解释原因。

## 8.10 "不知道装什么"的推荐路径

学生选"不知道"时，展示一个基于课程常见需求的推荐：

```
大多数刚学编程的同学会先装这一套：

  C / C++ 编译器    约 107 MB   写 C 语言作业用
  VS Code           约 95 MB    写代码的编辑器

合计约 202 MB，预计需要 3 分钟。
[就装这一套]   [我想自己挑]
```

**推荐必须给出理由与体积**，让学生知道自己在同意什么。
这也是"过程可解释"原则在第一步的体现。

## 8.11 设置页需要有什么（尽量少）

| 项 | 说明 |
|---|---|
| 环境存放位置 | 当前 ENV_ROOT，可改（改后说明"已装的环境不会移动，需要时我们可以帮你迁移"） |
| 代理设置 | 手动填写；留空则自动检测 |
| 更新通道 | 首期只有"稳定版"，字段保留 |
| 环境变量备份与还原 | 列出备份、查看差异、一键还原（见 `07`） |
| 清理旧版本 | 显示各版本占用空间，可清理 |
| 诊断信息 | "复制诊断信息"按钮（见 `12`） |

**不做的项**：不做主题切换、不做复杂的下载并发调节、不做"高级模式"开关——
每一项都是学生看不懂的负担。
