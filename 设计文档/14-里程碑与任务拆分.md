# EnvReady 设计文档 14 —— 里程碑与任务拆分

> 原则：**每个阶段结束时都必须有一个能跑、能演示、能验收的产物。**
> 不允许出现"写了两个月但什么都演示不了"的阶段。
> 阶段顺序对应申报研究路线，并遵循"先命令行、后图形"的工程判断。

---

## 14.1 阶段总览

| 阶段 | 名称 | 可演示产物 | 对应研究路线 |
|---|---|---|---|
| S0 | 工程准备 | 仓库、CI、规范落地；空程序能被构建并打印版本 | 需求调研（并行） |
| S1 | 清单与下载内核 | 命令行：`envready fetch mingw` 能下载并通过校验 | 清单格式与资源清单原型 |
| S2 | 安装与环境变量 | 命令行：装完 MinGW 后新窗口 `gcc --version` 可用；可一键还原 | 客户端核心引擎 |
| S3 | 图形客户端 | 一个零基础学生能独立完成安装 | 面向新手的图形客户端 |
| S4 | 自更新 | 故意发布一个坏版本，程序自动回退 | 自更新机制 |
| S5 | 云端巡检 | 上游发新版后清单自动更新 | 清单与镜像同步 |
| S6 | 试用与迭代 | 2 轮试用报告与改进 | 试用与反馈 |

**关键路径**：S1 → S2 → S3 → S6。S4 与 S5 可与 S3 部分并行（S4 依赖 S1 的下载引擎）。

## 14.2 S0 工程准备

**交付**：仓库结构（`01` 的 1.1）、三平台构建脚本、CI 骨架、代码规范落地。

任务清单：

- [ ] 初始化 Git 仓库、`.gitignore`、`LICENSE`（建议 MIT 或 Apache-2.0，与"开源"目标一致）
- [ ] 按 `01` 的 1.1 建立目录骨架与空的 `internal` 包（每个包只放一句包注释，说明职责）
- [ ] 建立 `cmd/envready`（启动器）与 `cmd/envready-gui`（主程序）两个入口，能编译、能打印版本
- [ ] CI：三平台 `gofmt` / `go vet` / `golangci-lint`（含 `errcheck`）/ `go test`
- [ ] 提交规范与分支策略（`01` 的 1.10）
- [ ] 设计文档入库（本套 15 份）

**验收**：`git push` 后 CI 三平台全绿；`envready --version` 与 `envready-gui --version` 有输出。

## 14.3 S1 清单与下载内核

**交付**：命令行工具，能拉清单、选组件、下载、校验、解压。

任务清单：

- [ ] `internal/paths`：三平台 APP_ROOT / ENV_ROOT 推导（含 `XDG_DATA_HOME`、用户名含空格与中文）
- [ ] `internal/manifest`：schema 解析、未知字段忽略、`client.json` 与分片加载、ETag 缓存、出厂快照降级
- [ ] `internal/manifest`：清单来源的多镜像拉取 + 测速择优
- [ ] `internal/download`：`GET + Range` 探测（不用 HEAD）、多镜像择优、`.part` + `.meta`、续传、分层超时、重试与换镜像、边下边算 SHA-256、取消
- [ ] `internal/download`：代理支持（设置项 + 环境变量 + 系统代理读取）
- [ ] `internal/download`：磁盘空间预检（下载前）
- [ ] `internal/archive`：魔术字节识别、zip / tar.gz / tar.xz / tar 解压、`strip_root`、符号链接与权限位保留
- [ ] `internal/archive`：7z 三级降级（`tar.exe` → 7-Zip → 下载 `7zr.exe`，含固定哈希校验）
- [ ] `internal/logging`：结构化日志、分级、轮转、脱敏
- [ ] `tools/`：清单生成脚本的**最小版本**（只支持 MinGW 一个组件，跑通 probe→resolve→verify→gen）
- [ ] 命令行：`envready fetch <组件> [--version <版本>] [--dry-run]`

**验收**：

1. `envready fetch mingw` 在一台干净机器上下载并解压成功，输出最终路径与 SHA-256 比对结果。
2. 断网中途恢复后能续传；服务端不支持 Range 时明确提示并重下。
3. 篡改包内容后校验失败并被拒绝。
4. 单元测试覆盖率达标（`download` / `archive` / `manifest`）。

**风险**：7z 三级降级是"未实测路径"最多的部分（前期脚本中这三个分支都没实跑过）——因此要在 S1 就补上真实测试。

## 14.4 S2 安装与环境变量（风险最高）

**交付**：命令行工具，能完整安装一个组件并配置环境变量，可回滚。

任务清单：

- [ ] `internal/install`：8 步流水线（预检 → 下载 → 校验 → 解压到 `.stage-` → `expect_files` 校验 → 原子改名 → 配置 → 自检）
- [ ] `internal/install`：`install_kind` 分支（`archive` / `installer` / `portable` / `npm` / `noop`）
- [ ] `internal/envvar`（Windows）：`HKCU\Environment` 读写、`REG_EXPAND_SZ` 保持、原始值读取、PATH 归一化去重、写后广播 `WM_SETTINGCHANGE`、回读校验
- [ ] `internal/envvar`（Unix）：登录 shell 判定（账号数据库优先）、zsh/bash/fish 三种语法、按组件归组的幂等块、行尾保持、备份
- [ ] `internal/envvar`：备份文件格式与"一键还原"
- [ ] `internal/envvar`：意图记录与启动时修复（`07` 的 7.4.2）
- [ ] `internal/envvar`：`HKCU` 之外的写操作一律禁止（加断言与测试）
- [ ] `internal/detect`：四级检测（自管记录 → PATH → 常见安装路径 → 环境根扫描）
- [ ] `internal/install`：`verify` 自检（新环境上下文、退出码 + 版本号解析、失败不判成功）
- [ ] `internal/component`：`.active.json` 与版本切换（PATH 条目**整条替换**）
- [ ] 命令行：`envready install <组件>`、`envready verify <组件>`、`envready rollback`
- [ ] 卸载/重置：只清理自己写入的内容

**验收**（这是整个项目的质量分水岭）：

1. Windows 干净机器上：`envready install mingw` 后，**新开** cmd 窗口 `gcc --version` 成功。
2. `envready rollback` 后用户 PATH 与备份逐字节一致。
3. 环境变量专项测试（`13` 的 13.5）全部通过，含：
   - 已装过参考实现（旧 `env-auto-setup` 标记块）的机器不重复追加
   - fish 用户不被写入 bash 语法
   - macOS 从 Finder 启动（`$SHELL` 为空）仍写对文件
   - PATH > 2000 字符不截断
4. 故障注入：写环境变量中途杀进程 → 重启后给出"完成/还原"选择，两种选择都得到一致状态。
5. **不需要管理员权限**，全程无 UAC。

## 14.5 S3 图形客户端

**交付**：面向零基础学生的引导式界面，能独立完成安装。

任务清单：

- [ ] Wails 工程接入（前端 embed 进二进制）；启动时检测 WebView2（Windows）并给出引导
- [ ] 主流程 5 步界面（`08` 的 8.2）
- [ ] 反技术黑话：文案全部走 `08` 的映射表；加一条自动化检查（在文案资源里搜索禁用词）
- [ ] 进度呈现：阶段区分（下载/解压/验证）、速度与剩余时间、未知总大小时的诚实进度、取消
- [ ] 授权询问：按 `08` 的 8.5 逐项询问，默认安全
- [ ] 结果页：成功展示自检真实输出 + 可复制的验证命令 + 下一步指引；失败展示"发生了什么/为什么/你可以怎么做"
- [ ] 「我做过什么」页面（`12` 的 12.6）
- [ ] 「复制诊断信息」（含脱敏与预览）
- [ ] 设置页（`08` 的 8.11）：环境位置、代理、备份与还原、清理旧版本
- [ ] 帮助页：症状导向的常见问题与一键动作（`12` 的 12.7）
- [ ] C/C++ 专项：VS Code 配置四文件生成 + 示例项目（`09` 的 9.5）
- [ ] 无障碍：键盘可操作、字号可读、最小窗口尺寸下不破版

**验收**：

1. **观察法测试**：找 3–5 名没写过代码的学生，只记录不提示，能独立完成安装；
   卡点被记录并修复。
2. 界面上不出现技术黑话（自动化检查 + 人工逐屏检查）。
3. 故意断网：错误页给出三条出路且按钮可用。
4. 装完 C/C++ 后，按示例项目的指引能在 VS Code 里编译并断点调试。

## 14.6 S4 自更新

**交付**：启动器 + 指针 + 健康检查 + 自动回退，全部可演示。

任务清单：

- [ ] 启动器：读指针、启动对应版本、`stable` 路径立即退出
- [ ] 启动器：修复模式（含不依赖主程序的极简对话框）
- [ ] 指针状态机与原子写（`02` 的 2.4）
- [ ] 健康检查：nonce 文件、两阶段标记、超时与重试、判定（`03` 的 3.4）
- [ ] 回退流程 + 用户告知
- [ ] 更新流程三段：清单更新（无需重启）/ 程序更新（重启）/ 启动器更新（顺手替换）
- [ ] "不打断任务"：安装进行中不切换指针
- [ ] "现在重启"的重启接力（启动器 `--wait-exit`）
- [ ] 单实例锁 + 唤起已有窗口 + 陈旧锁处理
- [ ] 版本目录 GC
- [ ] 全量测试矩阵（`03` 的 3.10，12 项）

**验收**：故意发布一个"启动即崩"的新版本，程序自动回到旧版并用人话告知用户；
`03` 的 12 项测试全绿。

## 14.7 S5 云端巡检与发布

**交付**：`envready-dist` 仓库 + 定时巡检 CI + 发布流水线。

任务清单：

- [ ] 建立 `envready-dist` 仓库与 `schema/v1` 的 JSON Schema
- [ ] `tools/` 完整版：支持首期 4–5 类组件的 probe / resolve / verify / gen
- [ ] 巡检 CI：每 6 小时（核心组件）、每天（其他）；差异比较；防抖动（两次一致、单调性、最小条数）
- [ ] 复核门禁：`recommended` 变更与校验和变更必须人工确认
- [ ] 失败告警：连续失败自动创建 Issue
- [ ] 发布流水线：三平台打包 + Release + 生成 `client.json`
- [ ] 清单纯 HTTPS 静态托管 + CDN 镜像（至少两个来源）
- [ ] 演练：故意让某组件上游发新版，计时到清单更新（验证 24 小时指标）

**验收**：演练在 24 小时内完成；清单被改坏时可 `git revert` 分钟级回滚且不影响已装用户。

## 14.8 S6 试用与迭代

任务清单：

- [ ] 第 1 轮：10–15 名学生（含 3–5 名观察法对象）；回收问卷与观察记录
- [ ] 按 `error_class` 统计失败原因分布，定位 Top 3 问题并修复
- [ ] 第 2 轮：≥30 名学生；回收有效问卷 ≥ 50 份、访谈 ≥ 5 场
- [ ] 成功率度量（`13` 的 13.7）：100 次自动化 + 30 名真实用户
- [ ] 编写使用文档、FAQ 与排错手册、新组件接入说明
- [ ] 总结报告；争取软件著作权登记材料

## 14.9 风险登记册

| # | 风险 | 影响 | 缓解 |
|---|---|---|---|
| R1 | 环境变量操作把用户机器改坏 | **最高**（失去信任、投诉） | 备份 + 意图记录 + 回读校验 + 一键还原；S2 阶段做专项与故障注入 |
| R2 | 代码签名证书缺失导致程序被拦 | 高（用户装不上） | 首期明确告知 + 文档指引；把签名列为加分项而非硬指标（与申报口径一致） |
| R3 | 上游下载地址频繁失效 | 中 | 巡检 + 多镜像 + 出厂快照 + 离线包 |
| R4 | 校园网代理/限速导致下载失败率高 | 中 | 代理设置 + 续传 + 镜像测速 + 离线包 |
| R5 | Go + Wails 的 WebView2 依赖 | 中 | 启动检测 + per-user 引导安装 + 保留 Fyne 降级预案（界面逻辑与内核解耦） |
| R6 | 依赖第三方 GUI 框架带来的不确定性 | 中 | 内核（命令行可跑）与界面严格分层；S1/S2 不依赖 GUI |
| R7 | 范围蔓延（想支持 29 个组件） | 中 | `05` 已明确首期只做 5 类；其余组件在清单格式中留字段但不实现 |
| R8 | 7z 三级降级路径未实测 | 中 | 优先选 `.zip` 包避开 7z；同时在 S1 补真实测试 |
| R9 | 时间不足导致 S4/S5 做不完 | 中 | S4/S5 与 S3 可并行；优先保证 S1–S3 的"可演示闭环" |
| R10 | 清单 schema 变更导致旧客户端不可用 | 中 | 双版本并存 + "旧客户端读新清单"回归测试（`13` 的 13.9） |

## 14.10 与项目约束的对应关系

| 项目硬约束 | 落在哪里 |
|---|---|
| 面向学生、UI 简洁 | `08` 全文；S3 的视觉与文案要求 |
| 所有事项简单明白地告诉用户我们干了什么 | `08`（说明模板、结果页）、`12` 的「我做过什么」页面 |
| 程序要有自更新机制 | `02`（目录与状态机）、`03`（更新机制）；S4 |
| 除 murig 已含语言外增加 C/C++ | `05` 的优先级表、`09` 全文；S2/S3 |
| 参考并兼容已有 MinGW 脚本 | `09` 的 9.2（逐条继承与非继承清单） |
| 代码不能混乱、注释说明功能 | `01` 全文（分包、注释模板、错误处理、红线清单） |
| 可以分步来写 | 本文档 S0–S6，每步都有可演示产物与验收 |
| 资源直取官方源、程序本体开源托管 | `10`（仓库划分、不托管安装包）、`11`（来源白名单） |
